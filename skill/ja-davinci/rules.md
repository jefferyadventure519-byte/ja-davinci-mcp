# 达芬奇操作踩坑清单

实测环境：DaVinci Resolve 免费版 21.0.4.5，Windows，控制层 davinci-resolve-mcp 4.10.4（经软件内桥接）。其他版本上行为可能不同，换版本后先跑一遍自检。
每条写的是「遇到什么 → 怎么做」。发现新坑请补在对应分类末尾。

## 一、连接与版本

- **R01 免费版 21.1 起接不上。** 达芬奇 21.1（2026 年 9 月）起免费版不再支持 Python 脚本，「工作区 → 脚本」里不再列出桥接脚本。→ 免费版只能用 21.0.x 及更早版本，装好后不要升级；要长期稳定用，换 Studio 版。
- **R02 每次打开达芬奇，桥接都要重新点一次。** 调用返回 `BRIDGE_UNAVAILABLE`。→ 请使用者点「工作区 → 脚本 → resolve_bridge」；项目管理器界面里脚本菜单是空的，要先打开一个工程。
- **R03 免费版不要调 Studio 才有的功能。** 从音频生成字幕、音频转写这类调用在免费版上会弹出一个升级提示框，提示框不关，后面所有调用都跟着失败，而且返回里看不出原因。→ 不调；语音转文字用本地转写工具。
- **R04 脚本接口做不到的事。** 改工程的播放帧率、读回当前渲染设置、改字幕条的文字和时间。→ 帧率请人在「项目设置」里改；渲染用固定的预设名起步，成片出来后用 ffprobe 核对。
- **R05 同一套工具不要注册两处。** Claude Code 的配置和桌面版配置里各写一份，会加载两次。→ 只留一处。

## 二、时间线：用文件导入，不要一个个片段搭

- **R06 用 FCPXML 一次导入。** 用接口逐个片段搭时间线又慢，又带不了转场和音量关键帧。→ 用 `tools/fcpx.py` 生成 FCPXML，`timeline.import_timeline_checked` 导入（路径不在临时目录时加 `require_temp_path=false`）。
- **R07 摄影机素材自带起始时间码。** FCPXML 里素材的 start 写 0，达芬奇直接拒绝导入，只报 Failed to import timeline。→ start 写成时间码对应的秒数，片段入点 = 时间码 + 文件内偏移（`fcpx.py` 已处理）。
- **R08 挂在主片段上的连接片段也要加父片段的时间码。** 漏加时导入成功，但这些片段被放到几小时之前，时间线起点变成负数。→ 导入后读时间线起止帧核对。
- **R09 29.97 帧素材的丢帧时间码。** 时间码写成 `01:05:11;18`（分号）时，按不丢帧换算会让入点偏几秒，导入不报错。→ `fcpx.py` 已按丢帧规则换算；导入后用 `clip_where` 读 `source_start_seconds` 核对。
- **R10 同一条轨上时间重叠的两个叠加层。** 导入后被并成一个时长异常的复合片段。→ 重叠的叠加层分到不同的轨。
- **R11 导入前先切到目标素材箱。** 控制层每次改动时间线都会自动留一份归档副本（名字带 `_archived_`），并把媒体池当前素材箱切到 Archive；这时再导入，时间线和素材会落进 Archive。→ 每次导入前先 `set_current_folder`；归档副本要不要删，问使用者。
- **R12 很短的音效导入后失联。** 短于约 0.5 秒的 WAV。→ 先补静音到 2 秒、转 48 kHz 再导入。

## 三、字幕

- **R13 把 SRT 落到可编辑的原生字幕轨。** 做法：`import_media` 导入 SRT → `add_track('subtitle')` → 把全部视频轨和音轨 `set_track_lock` 锁住 → `append_to_timeline(clip_ids=[SRT 的 id])` → 读首尾两条字幕的起止帧核对 → 解锁。不锁轨的话字幕会被排到时间线末尾；没有字幕轨时追加会「成功」但一条都没有。**禁止用带位置参数的写法（clip_infos）追加 SRT，达芬奇会直接闪退。**
- **R14 检查器里的「大小」不是像素。** 按 2160 高度计：1080p 时间线上「大小 88」实际字高约 44 像素；「位置 Y」是文字行中心到画面底边的距离。→ 要另外画字幕图层时按这个换算，不要按 88 像素画。
- **R15 字幕轨样式接口写不了，可以绕。** 把时间线导出成 DRT → `tools/sub_style.py` 写入字体、大小、位置 → `import_timeline` 导回成新时间线（画面、校色原样保留）。描边、投影、颜色写不了，请人在检查器「轨道样式」里设一次。默认样式下中文会回落成宋体样的字体。
- **R16 压制原生字幕。** 渲染设置里给 `ExportSubtitle: true, SubtitleFormat: "BurnIn"`。21.0.4.5 实测有效；有记录说 19.x 上不起作用。→ 渲一小段，抽帧确认字幕真的在画面上。原生字幕默认没有投影，白底上看不清。

## 四、画面与渲染

- **R17 停用轨道可能不生效。** 在从 DRT 导回的时间线上，`set_track_enable(false)` 返回成功，读回仍是启用，渲染里那条轨还在。→ 改用停用片段：`timeline_item.set_clip_enabled(false)`，读回并渲一小段确认。
- **R18 批量写校色会被拒绝。** 控制层 4.x 的 `apply_look_to_items` / `copy_grades` 默认拒绝，因为底层的复制调色会整体覆盖目标片段原有的调色且不留版本。→ 用 `timeline_item_color.safe_set_cdl` 逐个片段写；确实要批量复制时带 `acknowledge_trap=true`，并先确认目标片段上没有人工调过的东西。
- **R19 校色不要按素材文件夹一刀切。** 同一台摄影机换了取景，自动白平衡就变了，同一组数值套上去会偏色。→ 按镜头分组配，先出「原片｜校色后」对比图再定。去暖色用按通道调 power（只动中间调），不要按通道乘系数（会把白色物体染色）。
- **R20 用放大做近景。** 4K 素材放在 1080p 时间线上，放大 1.5 倍仍然清晰，可以把同机位的两段接成「全景 → 近景」。写法：缩放 1.5；横移 = (0.5 − 取景框中心 x) × 1920 × 1.5；纵移 = (取景框中心 y − 0.5) × 1080 × 1.5（x、y 按原画面的比例）。
- **R21 渲染到一半崩溃，日志里有 Pinned memory allocation failed。** 达芬奇默认最多用 75% 内存。→ 请人在「偏好设置 → 系统 → 内存与 GPU」里把达芬奇的内存占比调低；渲染前关掉其他吃内存的软件。
- **R22 免费版接口抓不了帧。** → 渲染成 MP4 后用 ffmpeg 抽帧看。
- **R23 「N 个离线」不一定是素材丢了。** 导入时间线后报离线，可能数的是转场。→ 用 `detect_missing_media` 核对再下结论。
- **R24 探针读回的入点可能少报一帧。** 结构探针给的 `source_start` 有时比实际少一帧。→ 判断成片有没有差帧，以抽帧比对为准，不以这个读数为准。

## 五、省上下文

- **R25 有些调用的返回很长。** `append_to_timeline` 会把整条时间线每条轨的片段编号前后各列一遍；`prepare_render_job` 会列出队列里所有任务。→ 能合并的操作合并做，不要为了确认反复调用；需要逐项核对时用 `get_start` / `get_end` 这类小调用。
